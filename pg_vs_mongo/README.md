# Сравнение производительности PostgreSQL и MongoDB

## Цель
Провести нагрузочное тестирование операций с пользовательскими лайками, рецензиями и закладками, чтобы определить наиболее подходящее хранилище данных.

## Запуск тестирования

1. Перейти в папку `pg_vs_mongo`

2. Поднять и настроить базы данных (таблицы и индексы создадутся автоматически):
   ```bash
   docker compose up -d

3. Наполнить базы тестовыми данными:
    ```
    python populate.py

4. Запустить тестирование:
    ```
    python load_test.py

Результаты сохраняться в файл load_testing_results.json

## Общие выводы

* MongoDB — хорош для лайков/дизлайков: быстрый, масштабируемый, быстро индексирует.

* PostgreSQL — лучше для:
  * агрегатов с фильтром по связанной таблице (средние оценки по ревью),

  * поиска по таблицам с умеренно растущим объямом данных (Рецензии, закладки)

## Рекомендуемая архитектура:

* Лайки и дизлайки хранить в MongoDB

* Рецензии, их оценки, закладки — в PostgreSQL


## Описание реализации сервиса:

Принято решение реализовывать отдельный сервис, основываясь на оценке следующих критериев:

1) Масштабируемость:

    Хранение пользовательской активности со временем может стать самым нагруженным компонентом системы. Вынос в отдельный сервис позволит масштабировать его независимо от других частей приложения.

2) Разделение ответственности:

    Один сервис — одна зона ответственности. Это улучшает поддержку, тестирование и понимание кода командой.

3) Гибкость хранения данных:

    Можно использовать оптимальное хранилище для каждого типа данных,например, MongoDB для лайков, PostgreSQL для рецензий и закладок.

4) Изоляция ошибок:

    Проблемы с пользовательским UGC-сервисом (например, пиковые нагрузки или ошибки) не повлияют на основное приложение, если они разнесены.

5) Удобство мониторинга:

    Возможность отслеживать нагрузку и ошибки, возникающие в UGC-сервисе, отдельно от сервиса, отвечающего за контент.

При этом, недостатки реализации отдельного сервиса на фоне вышеуказанных преимуществ выглядят незначительными:

* Сетевые задержки между сервисами.

* Рост нагрузки на postgres из-за дополнительных запросов на рецензии, оценки и закладки.
