### Roadmap по выполненным заданиям

1. Кастомный бэкэнд и аутентификация пользователей реализован в приложении users django-проекта admin_panel.
Принцип работы:
При работающем сервисе auth_api авторизация доступна, в частности для суперпользователей и админой в django-админке, только если они были зарегистрированы через auth_api. При первой авторизации их данные сохраняются локально для возможности управления контентом в случае отказа auth_api.
<br> При запуске auth_api суперпользователь создаётся автоматически согласно значениям переменных окружения.

2. Настройки трассировки прописаны в main.py сервиса auth_api. Трейсы отправляются в контейнеризированный jaeger-сервер. Трейсам http-запросов присваивается атрибут htpp.request_id, значение которого берётся из хедера X-Request-Id, назначаемого nginx'ом.

3. Nginx сконфигурирован на обработку одного запроса в секунду с ведром в 5 запросов для каждого ip.

4. В качестве OAuth-провайдера выбрал YandexId. Работа клиентской части основана на эндпоинтах: "/auth/yandex/login", "/auth/yandex/token", а также и "/auth/yandex/reconcile/", если нужно подтвердить связь указанной при авторизации у провайдера почты с владельцем зарегистрированного на неё аккаунта.<br><br>
"/auth/yandex/login" - эндпоинт для редиректа пользователя на страницу авторизации YandexId;<br>
"/auth/yandex/token" - эндпоинт на который yandex перенаправляет пользователя после авторизации для локальной аутентификации и авторизации;<br>
"/auth/yandex/reconcile/" - пока без реализации.


5.6. Эти задания пропущены, тк по согласованию с куратором работу выполнил без индивидуально.
